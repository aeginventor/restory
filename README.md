# restory

어떤 작품을 언제 봤고, 그때 무엇을 느꼈는지 남기는 개인 감상 아카이브입니다. 같은 작품을 다시 본 날에는 새 기록을 추가해 예전 감상과 함께 읽을 수 있습니다.

영화, 드라마, 애니메이션, 책, 웹툰과 만화, 게임을 다룹니다. 날짜를 정확히 기억하지 못해도 연월, 연도, 날짜 모름으로 기록할 수 있습니다.

[restory 열기](https://restory-vert-six.vercel.app)

## 먼저 실행하기

Node.js 24와 npm을 사용합니다. 저장소를 복제한 뒤 프로젝트 폴더에서 실행하세요.

```bash
git clone https://github.com/aeginventor/restory.git
cd restory
npm ci
npm run dev -- --port 34761
```

[http://127.0.0.1:34761](http://127.0.0.1:34761)을 엽니다. 다른 프로젝트와 구분하도록 34761 포트를 사용합니다. Supabase 환경변수를 입력하지 않아도 체험 모드로 실행할 수 있습니다.

**체험 기록은 현재 브라우저에 저장됩니다.** 새로고침해도 남지만 다른 기기와 동기화되지 않습니다. 브라우저 데이터를 지우면 기록도 사라질 수 있으므로 보관할 기록은 JSON으로 내보내세요. 체험 모드의 공개 감상은 실제 이용자의 게시물이 아닙니다.

## 포함된 기능

- 작품 검색과 직접 등록, 감상 기록 작성, 수정과 삭제
- 같은 작품의 여러 감상 기록, 정확한 날짜와 부분 날짜
- 제목, 매체, 연도, 감정 태그에 따른 기록 찾기와 마음에 남은 기록 표시
- 작품별 감상 이력, JSON 내보내기와 다시 가져오기
- 작성 중인 글의 임시 보관과 복원, 다른 탭의 수정을 덮어쓰지 않는 저장
- 공개 감상 전체 검색과 작품별 공개 감상 모아 보기
- 이메일 로그인과 계정별 저장을 위한 Supabase 연결 코드
- 기록별 공개와 공개 취소, 스포일러 가리기와 공개 감상 신고
- 닉네임 변경, 계정 삭제를 위한 데이터 처리

이 저장소에는 화면, 저장소 연결, 데이터베이스 마이그레이션, 테스트와 GitHub Actions 설정이 포함됩니다. Supabase 프로젝트에 초기 스키마를 적용했고 Vercel에 첫 버전을 배포했습니다. 소유자가 직접 가입과 이메일 인증을 마쳤고 실제 계정의 비공개 저장, 부분 날짜, 새로고침 후 유지와 수정을 확인했습니다. 다른 기기에서의 동기화는 별도 확인이 필요합니다.

2026년 10월 1일 최초 구현 `1b59f72`에서 lint, 타입 검사, 단위 테스트 25개, 데스크톱과 모바일 브라우저 테스트 16개, PostgreSQL 권한 검증 67개와 프로덕션 빌드가 통과했습니다. [GitHub Actions 실행 결과](https://github.com/aeginventor/restory/actions/runs/36861827389)에서 확인할 수 있습니다. 실제 Supabase API의 공개 목록 응답과 비로그인 개인 기록, 프로필 접근 차단도 확인했습니다.

2026년 10월 7일에는 첫 검토에서 찾은 기록 손실 경로와 미완성 흐름을 수정했습니다. 책갈피가 다른 탭의 수정을 덮어쓰던 문제, 저장 중 입력과 새로고침으로 글을 잃던 문제를 고치고, 공개 감상 검색을 서버에서 전체 대상으로 바꿨으며, 내보낸 JSON 가져오기와 손상된 체험 저장소의 원본 내려받기를 추가했습니다. 자세한 내용은 [검토 가이드](docs/review-guide.md)에 있습니다.

배포 주소에서 HTTP 200 응답, 데스크톱과 모바일 화면, 공개 감상 목록 연결과 가입 폼을 확인했습니다. 로그인하지 않은 첫 화면의 감상은 체험용 예시이며 실제 공개 감상 목록은 비어 있습니다. 검증용 감상 한 건은 소유자 승인 후 삭제했습니다.

## 실제 계정으로 사용하기

프로젝트 소유자의 Supabase와 로컬 환경은 연결되어 있습니다. 새 환경에서 실행하려면 [Supabase 설정 안내](docs/supabase.md)에 따라 별도 프로젝트와 `.env.local`을 준비합니다. 실제 값은 Git에 올리지 않습니다.

본인 계정으로 가입과 이메일 확인을 마친 뒤 기록을 저장하고 새로고침, 로그아웃 후 재로그인으로 유지 여부를 확인합니다. 일반 이용자의 가입은 Google 로그인으로 받습니다. Supabase의 Google 제공자를 설정하고 `NEXT_PUBLIC_GOOGLE_LOGIN=true`를 넣으면 로그인 화면에 버튼이 나타납니다. 그 전까지는 이메일 로그인만 보입니다. [Google 로그인 설정](docs/supabase.md#가입-방식-google-로그인)

체험 기록은 실제 계정에 자동으로 복사되지 않습니다. 계정 연결 전후의 데이터는 별도로 유지합니다.

## 검증 명령

```bash
npm run check
npx playwright install chromium
npm run test:e2e
```

`check`는 lint, 타입 검사, 단위 테스트, 빌드를 순서대로 수행합니다. 브라우저 테스트는 Playwright가 34761 포트에 별도 서버를 실행해 체험 모드를 검사하므로, 같은 포트의 개발 서버를 먼저 종료합니다. 실제 Supabase 권한 검증은 [Supabase 설정 안내](docs/supabase.md)를 따릅니다. 체험 테스트 통과가 운영 데이터베이스 권한 검증을 대신하지는 않습니다.

PostgreSQL 서버 바이너리가 설치되어 있다면 `bash supabase/tests/run-security.sh`로 임시 데이터베이스에서 권한 테스트를 실행할 수 있습니다. GitHub Actions에서도 이 검사를 별도 작업으로 실행합니다.
