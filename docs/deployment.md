# Vercel 배포와 복구

현재 저장소는 로컬에서 실행하고 빌드할 수 있도록 구성되어 있습니다. Vercel 프로젝트 연결, Supabase 프로젝트 생성과 운영 인증 설정은 별도 작업입니다. 이 문서는 아직 배포하지 않은 주소를 실제 서비스 주소로 가정하지 않습니다.

## 배포 전 준비

1. 배포할 커밋의 `npm run check`와 체험 브라우저 검사 결과를 확인합니다.
2. [Supabase 설정 안내](supabase.md)에 따라 개발용 데이터베이스와 인증을 연결합니다.
3. Vercel 계정에 로그인하고 `aeginventor/restory` 저장소 접근을 허용합니다.

Vercel에서 저장소를 가져오면 Next.js 프로젝트로 설정합니다. 이 저장소 자체가 프로젝트 루트이므로 Root Directory는 `.`입니다. 상위 컴퓨터 폴더의 이름인 `restory`를 다시 입력하지 않습니다. Node.js는 로컬과 CI에 맞춰 24로 선택하고, 설치는 `npm ci`, 빌드는 `npm run build`를 사용합니다. 자세한 감지와 배포 방식은 [Vercel Next.js 안내](https://vercel.com/docs/frameworks/full-stack/nextjs)를 참고하세요.

## 환경 구분

| 환경                | 데이터                        | 용도                                 |
| ------------------- | ----------------------------- | ------------------------------------ |
| 로컬 체험           | 브라우저 저장소와 예시 데이터 | 외부 계정 없이 화면과 기록 흐름 확인 |
| 로컬 개발과 Preview | 개발용 Supabase 프로젝트      | 로그인, 권한과 공유 기능 검사        |
| Production          | 운영용 Supabase 프로젝트      | 실제 사용자 기록                     |

`.env.example`과 Supabase 안내에 명시된 변수만 해당 Vercel 환경에 입력합니다. 개발용과 운영용 프로젝트의 주소와 키를 혼동하지 않습니다. 브라우저용 공개 키와 관리자 비밀키는 서로 바꿔 넣을 수 없습니다. 환경변수 변경을 반영하려면 해당 환경을 다시 배포해야 합니다. [Vercel 환경변수 안내](https://vercel.com/docs/environment-variables)

Supabase Authentication의 Site URL과 허용 리디렉션 주소를 실제 배포 주소에 맞춥니다. 프로젝트에서 사용하는 인증 콜백 경로는 [Supabase 설정 안내](supabase.md)를 따릅니다. 로그인 메일이 로컬 주소나 다른 프로젝트로 돌아가지 않는지 확인합니다.

## 미리보기 확인

GitHub 브랜치 변경으로 생성한 Preview 주소에서 다음을 확인합니다. 운영용 데이터 대신 별도의 테스트 계정을 사용합니다.

- 로그인 메일을 받아 브라우저에서 인증 완료
- 감상 저장 후 새로고침과 재로그인, 다른 기기에서 조회
- 부분 날짜, 재감상, 수정, 삭제와 내보내기
- 다른 계정과 비로그인 요청에서 개인 기록 접근 차단
- 기록 공개, 스포일러 펼치기, 공개 취소 후 접근 차단
- 좁은 화면에서 글 작성과 키보드 조작

체험 모드만 표시되는 경우에는 브라우저 화면이 열린 것과 Supabase 연결 성공을 구분합니다. 배포된 기능의 실제 검증 결과를 PR에 남깁니다.

## 운영 반영과 비용

미리보기를 검토한 뒤 운영에 사용할 브랜치를 확인하고 반영합니다. Vercel에서 운영 브랜치를 `main`으로 설정했다면 해당 브랜치의 변경이 운영 배포로 이어질 수 있습니다. 실제 연결된 브랜치를 먼저 확인합니다. [Vercel Git 배포 안내](https://vercel.com/docs/git)

배포 시점에 [Vercel 요금](https://vercel.com/pricing)과 [Supabase 요금](https://supabase.com/pricing)을 확인합니다. 무료 제공량과 메일 발송 조건은 바뀔 수 있으므로 고정된 비용을 보장하지 않습니다. 유료 전환이나 도메인 구매는 필요한 경우 별도로 결정합니다.

## 문제 발생 시

화면 변경으로 문제가 생기면 Vercel에서 이전 정상 배포를 확인하고 되돌리는 절차를 진행합니다. 새 배포의 환경변수와 인증 리디렉션 설정도 함께 확인합니다. [Vercel 롤백 안내](https://vercel.com/docs/instant-rollback)

애플리케이션을 이전 버전으로 돌려도 데이터베이스 마이그레이션은 되돌아가지 않습니다. 데이터 구조를 바꾸기 전에는 기존 코드와의 호환성과 복구 방법을 검토합니다. 실제 기록이 있는 데이터베이스에서 초기화 명령을 실행하지 않습니다. 데이터 복원은 해당 Supabase 프로젝트의 백업 제공 여부와 복구 지점을 확인한 뒤 수행합니다.
