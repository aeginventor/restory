# restory 제품과 데이터 정책

## 만들려는 이유

시간이 지나면 어떤 작품을 봤는지, 언제 봤는지, 당시 무엇을 느꼈는지 잊기 쉽습니다. restory는 기록을 남기는 수고를 줄이고, 예전의 내가 좋아했던 이야기와 감상을 다시 읽을 수 있도록 만듭니다. 같은 작품을 본 다른 사람의 감상도 작품을 중심으로 찾아볼 수 있게 합니다.

핵심 사용 흐름은 작품 선택, 감상 시점 입력, 필요한 만큼 글을 쓰고 저장하기입니다. 길게 쓰지 않아도 기록이 남아야 하며, 같은 작품을 다시 접했을 때는 과거 글을 고치는 대신 새 감상을 추가할 수 있어야 합니다.

## 이번 버전의 범위

| 영역   | 동작                                                                        |
| ------ | --------------------------------------------------------------------------- |
| 작품   | 등록된 작품 검색, 제목과 매체를 입력해 직접 등록, 창작자와 발표 연도는 선택 |
| 기록   | 감상 시점, 한 줄 감상, 긴 글, 감정 태그, 마음에 남은 기록 표시              |
| 재감상 | 한 작품에 여러 기록을 보존하고 작품 상세에서 함께 읽기                      |
| 찾기   | 제목, 매체, 감상 연도와 태그로 필터링                                       |
| 보관   | 수정, 삭제, JSON 내보내기                                                   |
| 계정   | 이메일 로그인, 닉네임, 본인 기록 저장, 계정 삭제                            |
| 공유   | 사용자가 선택한 기록만 공개, 공개 취소, 스포일러 가리기, 신고               |

계정과 공유 기능은 Supabase 프로젝트를 연결한 환경에서 사용합니다. 체험 모드는 브라우저 안에서 이 흐름을 확인하기 위한 별도 저장소입니다.

## 데이터 원칙

작품과 감상 기록을 분리합니다. 제목이 같은 작품도 다른 창작물일 수 있으므로 제목만으로 자동 병합하지 않습니다. 매체, 창작자, 발표 연도를 함께 확인하고, 작품 ID로 기록을 연결합니다.

감상 시점과 기록 작성 시점도 구분합니다. 감상 시점은 `day`, `month`, `year`, `unknown` 중 하나의 정밀도를 가집니다. 내부 저장이나 정렬을 위해 날짜 형태를 정규화하더라도 화면과 내보내기에서는 정밀도를 보존합니다. 연도만 기억하는 기록을 1월 1일에 본 것처럼 표시하지 않습니다. 날짜를 모르면 비워 두고 작성일과 구별합니다.

| 데이터    | 의미                                                                |
| --------- | ------------------------------------------------------------------- |
| 작품      | 제목, 매체, 창작자, 발표 연도와 공개 여부                           |
| 감상 기록 | 작품 ID, 작성자, 감상 시점과 정밀도, 글, 태그, 공개와 스포일러 설정 |
| 프로필    | 계정 ID와 공개 표시용 닉네임                                        |
| 신고      | 대상 공개 감상과 신고 사유, 운영 처리 정보                          |

개인 작품과 새 감상 기록은 기본 비공개입니다. 공개하는 동작과 글을 저장하는 동작을 구분하고, 공개 전에 표시될 작품 정보와 글을 확인할 수 있어야 합니다. 공개 감상에 이메일을 표시하지 않습니다.

공개 취소와 삭제 후에는 공개 조회에서 내용을 반환하지 않아야 합니다. 화면에서 버튼을 숨기는 것만으로 접근 권한을 제한하지 않고, 데이터베이스 정책과 서버에서도 검사합니다. 사용자가 다른 사람의 기록 ID를 직접 요청해도 비공개 기록을 읽거나 수정할 수 없어야 합니다.

체험 데이터는 클라우드 계정에 자동 업로드하지 않습니다. 샘플 감상은 예시로 작성한 내용이며 실제 사용자 활동이나 이용자 수처럼 표현하지 않습니다.

## 화면과 문체

한국어 기록을 오래 읽어도 부담스럽지 않은 본문 크기와 줄 간격을 사용합니다. 작품 목록, 시간순 기록, 긴 감상 글의 분량에 맞춰 배치를 정합니다. 큰 홍보 제목, 반복되는 색상 카드, 장식용 영어 문구는 줄이고 기록 내용을 우선합니다.

저장 실패 시 입력한 글을 보존하고 실패 사실을 알려줍니다. 빈 기록함, 검색 결과 없음, 긴 제목, 긴 감상, 작은 화면과 키보드 조작도 사용 흐름에 포함합니다.

## 다음에 판단할 일

먼저 실제 사용자가 짧은 감상을 쉽게 남기고, 며칠 뒤 스스로 다시 기록하는지 확인합니다. 외부 작품 검색은 직접 등록이 얼마나 불편한지 확인한 뒤 많이 쓰는 매체부터 추가합니다. API를 도입할 때는 작품 식별자, 중복 처리와 이미지 이용 조건을 함께 정합니다.

회차별 진도 관리, 팔로우, 개인 메시지, 인기 순위, 추천 알고리즘과 AI 감상 생성은 이번 범위에 넣지 않습니다. 공개 운영을 시작할 때는 신고를 확인할 담당자, 개인정보 처리 안내, 데이터 보관과 삭제 절차를 실제 운영 방식에 맞춰 정합니다.
