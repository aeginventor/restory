# Codex 후속 작업 프롬프트

프로젝트 폴더에서 아래 프롬프트를 사용합니다. 현재 코드를 확인한 뒤 필요한 변경을 이어가는 요청입니다. 이미 구현된 기능을 새 프로젝트로 다시 만들지 않도록 했습니다.

## 1. 로컬 기능 확인과 수정

```text
이 restory 저장소의 AGENTS.md, README.md, docs/product.md를 읽고
현재 Git 상태와 구현을 확인해줘. 기존 변경은 보존해줘.

체험 모드를 실행해 작품 등록, 짧은 감상 저장, 부분 날짜, 재감상,
필터, 수정, 삭제와 JSON 내보내기를 브라우저에서 확인해줘.
같은 작품의 옛 감상이 덮어써지면 안 되고, 연도만 아는 기록을
정확한 날짜로 표시하면 안 돼.

모바일과 긴 글, 빈 상태, 키보드 사용, 저장 실패도 확인하고
발견한 실제 문제를 수정해줘. 화면에 불필요한 장식과 영어 표어를 추가하지 마.

기능 브랜치에서 작업하고 npm run check와 변경 흐름의 브라우저 검사를 실행해줘.
완료한 변경과 검증 결과를 커밋하고 origin에 push한 뒤 초안 PR을 만들어줘.
실행하지 못한 검사를 통과했다고 보고하지 마.
```

## 2. Supabase 프로젝트 연결

```text
restory에 준비된 Supabase 연결을 실제 프로젝트에 적용해줘.
먼저 docs/supabase.md, 환경변수 예시, 마이그레이션과 인증 코드를 읽어줘.

Supabase 프로젝트: [대시보드 주소 또는 프로젝트 식별자]
로컬 주소: [실행 중인 주소]

실제 키를 대화나 로그에 출력하지 말고 적절한 환경 설정에 저장해줘.
내가 브라우저에서 해야 하는 계정 생성, 인증과 설정 입력만 구체적으로 알려줘.
기존 데이터가 있다면 삭제하거나 초기화하지 마.

이메일 로그인, 세션 만료, 저장 실패 시 글 보존, 닉네임 변경,
계정 삭제와 다른 기기에서의 조회를 확인해줘.
테스트 사용자 A, B와 비로그인 상태에서 비공개 작품과 기록의
조회, 수정, 삭제, 잘못된 작품 ID 연결이 차단되는지 검증해줘.
공개와 공개 취소, 스포일러 표시, 신고 처리 권한도 확인해줘.
체험 데이터는 계정에 자동으로 섞지 마.

수정이 필요하면 기능 브랜치에서 구현하고 검사한 뒤 커밋, push, 초안 PR을 만들어줘.
로컬 검사와 실제 프로젝트에서 확인한 결과를 구분해서 보고해줘.
```

## 3. 작품별 공개 감상 검토

```text
restory의 작품별 공개 감상 흐름을 실제 사용자가 이용할 수 있는지 검토하고 수정해줘.
현재 코드와 docs/product.md를 기준으로 작업해줘.

새 기록의 기본값은 비공개여야 하고 공개 전에 공개할 작품 정보와 글을
확인할 수 있어야 해. 이메일은 노출하지 마.
다른 사람의 감상이 같은 공통 작품에서 모이는지 확인하고,
동명 작품을 제목만으로 자동 합치지 마.

공개 취소와 삭제 뒤 공개 목록, 상세 요청과 캐시에서 내용이 제거되는지 확인해줘.
스포일러는 펼치기 전까지 가리고, 신고와 운영자 숨김 권한을 확인해줘.
운영자를 임의로 지정하거나 기존 사용자의 권한을 변경하지 마.

팔로우나 추천 알고리즘을 추가하지 말고 현재 공유 흐름의 문제를 해결해줘.
검증 후 커밋, push, 초안 PR을 만들고 문서를 구현에 맞춰 갱신해줘.
```

## 4. Vercel 미리보기 배포

```text
docs/deployment.md에 따라 restory를 Vercel 미리보기로 배포해줘.
현재 GitHub 저장소와 브랜치, 검사 결과, 환경변수와 Supabase 설정을 먼저 확인해줘.

Vercel 프로젝트: [기존 프로젝트 주소 또는 새로 연결]
사용할 Supabase 프로젝트: [개발 또는 미리보기용 프로젝트]

계정 연결이나 브라우저 인증이 필요하면 내가 직접 할 순서를 알려줘.
운영 데이터와 테스트 데이터를 분리하고, 미리보기 환경의 인증 리디렉션을 설정해줘.
비밀키와 실제 환경변수 값을 로그나 Git에 남기지 마.

배포된 주소에서 로그인, 기록 저장, 재접속, 수정, 삭제,
공개와 공개 취소, 비공개 접근 차단, 모바일 기록 흐름을 확인해줘.
현재 요금제와 비용 발생 조건은 공식 문서에서 확인해줘.
유료 전환과 도메인 구매는 진행하지 마.

배포 주소, 검증 결과, 남은 문제와 복구 방법을 남겨줘.
운영 반영은 내가 미리보기를 확인하고 요청한 뒤 진행해줘.
```

처음 개발을 시작할 때의 단계는 개인 기록, 실제 저장, 공개 감상, 배포 순서였습니다. 현재는 최초 구현과 Supabase 연결, Vercel 첫 배포가 끝났습니다. 후속 작업은 실제 가입과 로그인 후 저장 검증, 일반 가입용 SMTP 연결, 개발과 운영 데이터베이스 분리부터 이어갑니다. 기존 프로젝트에 초기 마이그레이션을 다시 실행하지 않습니다. 실제 클라우드 검증이 끝나기 전에는 운영 서비스가 완성되었다고 표현하지 않습니다.
