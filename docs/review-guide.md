# 검토 가이드와 개선 프롬프트

첫 구현과 배포가 끝난 뒤 restory를 검토하는 기준과, 발견한 문제를 고칠 때 Codex나 다른 코딩 도구에 전달할 프롬프트를 정리합니다. 2026년 10월 1일 코드 검토에서 찾은 문제와 10월 7일에 반영한 수정도 함께 기록합니다.

## 검토 기준

restory는 기록을 잃지 않는 것이 가장 중요한 서비스입니다. 검토는 다음 순서로 진행합니다.

1. 기록 손실. 저장 중, 새로고침, 탭 두 개, 네트워크 지연, 브라우저 저장소 손상 상황에서 사용자가 쓴 글이 사라지거나 예전 내용으로 덮이는 경로를 찾습니다.
2. 데이터 경계. 체험 데이터와 계정 데이터가 섞이지 않는지, 비공개 기록이 공개 목록, 상세 주소, 검색에 노출되지 않는지 확인합니다. 이메일과 계정 ID가 공개 응답에 포함되면 안 됩니다.
3. 보관 서비스로서의 완결성. 내보낸 파일을 다시 가져올 수 있어야 하고, 손상된 저장소에서도 개발자 도구 없이 원본을 꺼낼 수 있어야 합니다.
4. 공개 감상 흐름. 검색이 전체를 대상으로 동작하는지, 작품별 공개 감상으로 이동하는 경로가 있는지, 결과가 없을 때 안내가 있는지 확인합니다.
5. 회귀 테스트. 위 상황을 단위 테스트, 브라우저 테스트, 데이터베이스 권한 테스트 중 맞는 층위에 추가합니다. 단일 탭의 정상 저장만 검사하는 테스트로는 손실 경로를 잡지 못합니다.

검토는 먼저 코드와 테스트를 읽고 재현 경로를 적은 뒤, 운영 데이터나 계정을 건드리지 않는 범위에서 체험 모드로 재현합니다. 운영 데이터베이스 변경은 마이그레이션 파일로 남기고 적용 여부를 문서에 기록합니다.

## 2026년 10월 1일 검토 결과와 반영

| 우선순위 | 문제 | 반영 |
|---|---|---|
| P1 | 책갈피를 누르면 화면이 들고 있던 예전 본문, 날짜, 태그 전체가 다시 저장되어 다른 탭의 수정을 덮어썼다. | `setFavorite`로 책갈피만 부분 수정한다. 본문 수정은 열었을 때의 `updatedAt`을 함께 보내 다른 곳에서 바뀐 기록이면 저장을 거부하고 입력을 그대로 남긴다. |
| P1 | 저장 요청 중에도 입력이 가능해 클릭 시점의 글만 저장되고 이후 덧쓴 글이 사라졌다. | 저장 중에는 폼 전체를 잠그고 중복 제출을 막는다. |
| P1 | 새로고침이나 탭 종료 시 작성 중인 글을 잃었다. | 입력을 계정별 키로 브라우저에 임시 보관하고, 다음에 폼을 열 때 복원할지 선택하게 한다. 저장이나 명시적 닫기 뒤에는 지운다. 로그아웃하면 그 계정의 초안을 모두 지운다. 작성 중 페이지를 떠나면 브라우저가 확인을 요청한다. |
| P2 | 공개 감상 검색이 먼저 불러온 20건에만 적용됐고 결과가 없어도 안내가 없었다. | 검색어를 서버 함수 `list_public_entries(p_work_id, p_page, p_query)`로 보내 전체에서 찾고 페이지를 나눈다. 제목, 창작자, 감상 내용, 태그를 대상으로 하며 닉네임과 이메일은 검색하지 않는다. 결과가 없으면 안내를 표시한다. |
| P2 | 내보낸 JSON을 다시 가져올 수 없었다. | 설정에서 restory가 내보낸 파일을 읽어 미리보기(새 작품, 새 감상, 중복 수)를 보여준 뒤 비공개로 추가한다. 작품은 제목, 매체, 창작자, 연도로 맞추고 같은 내용의 감상은 건너뛴다. 같은 파일을 두 번 넣어도 늘지 않는다. |
| P2 | 공개 작품별 감상으로 이동하는 경로가 없었고 비로그인 상태의 `/works/:id`는 빈 화면이었다. | 공개 카드의 제목이 작품별 공개 감상 화면으로 이어진다. 내 아카이브에 없는 작품 ID로 열면 공개 감상을 모아 보여준다. |
| 추가 | 체험 저장소가 손상되면 오류만 보이고 설정도 열 수 없었다. | 오류 화면에서 읽을 수 없는 원본을 파일로 내려받고, 확인 뒤 체험 데이터를 초기화할 수 있다. 재시도는 여전히 원본을 덮어쓰지 않는다. |

반영 내용의 검증은 단위 테스트(`tests/import.test.ts`, `tests/demo-repository.test.ts`), 브라우저 테스트(`e2e/review.spec.ts`), 데이터베이스 권한 테스트(`supabase/tests/security.sql`의 검색 항목)에 있습니다. 운영 Supabase 프로젝트에는 `supabase/migrations/202610010002_public_search.sql`을 2026년 10월 7일에 적용했습니다.

## 아직 남은 항목

- 일반 이용자 가입은 Google 로그인으로 받기로 했습니다. 코드와 설정 순서는 준비됐고, Google OAuth 클라이언트 발급과 Supabase 제공자 입력은 소유자가 합니다.
- 두 계정과 다른 기기에서의 실사용 검증. 동시 수정 충돌 안내는 체험 모드와 코드 수준에서 확인했고 실제 계정 두 개로는 아직 확인하지 않았습니다.
- 개발용과 운영용 Supabase 프로젝트 분리.
